# USER DOCUMENTATION — Inception

## 1. Starting the project

From the root directory of the repository, execute:

```bash
make
```

This command builds the required Docker images and starts the services in the background.

To check the status of the containers:

```bash
make ps
```

## 2. Stopping the project

To stop the containers without deleting persistent data:

```bash
make stop
```

To stop and remove the containers and the Compose network:

```bash
make down
```

Persistent data is stored separately from the containers and is preserved when the containers are removed.

## 3. Accessing the services

### WordPress website

Open the following address in your browser:

```text
https://<DOMAIN_NAME>
```

Replace `<DOMAIN_NAME>` with the domain configured in your `.env` file.

The website is served through Nginx using HTTPS on port 443.

If a self-signed certificate is used, your browser may display a security warning.

### WordPress administration panel

The WordPress administration interface is available at:

```text
https://<DOMAIN_NAME>/wp-admin
```

Use the administrator credentials configured during the initial WordPress installation.

### Adminer

Adminer provides a web interface for managing the MariaDB database.

Its web interface is configured under the `/adminer/` web path.

Use the following connection information:

- System: MySQL
- Server: `mariadb`
- Username: the database user configured in `.env`
- Password: the database password configured in `.env`
- Database: the configured WordPress database

### Mailpit

Mailpit captures outgoing emails generated by WordPress.

Its web interface is configured under the `/mailpit/` web path.

Use the URL configured in the Nginx reverse proxy configuration.

Mailpit uses:
- SMTP port: `1025`
- Web interface port: `8025` internally

### FTP

The FTP service provides access to the shared WordPress files.

The FTP service uses:
- Control port: `21`
- Passive ports: `21100-21110`

The FTP service is available to containers connected to the Docker network. Its ports are not published to the host in the current configuration.

Use the FTP username and password configured for the service.

## 5. Credentials management

Credentials are stored in the `.env` file located in the `srcs/` directory.

This file contains the configuration required by the different services, including:

- MariaDB database name and credentials.
- WordPress administrator account.
- WordPress additional user account.
- FTP account credentials.
- Domain name.
- Mailpit version.

To inspect the configuration:

```bash
cat srcs/.env
```

Do not share the output publicly.

## 6. Checking that services are running

To list running containers:

```bash
make ps
```

To inspect service logs:

```bash
make logs
```

To inspect a specific service:

```bash
docker logs nginx
docker logs wordpress
docker logs mariadb
docker logs redis
docker logs ftp
docker logs adminer
docker logs mailpit
```

To check the Docker network:

```bash
docker network ls
```

To list persistent Docker volumes:

```bash
docker volume ls
```

## 7. Persistent data

The project uses two persistent storage volumes:

- `mariadb_data`: stores MariaDB database files.
- `wordpress_data`: stores WordPress files.

Their data is stored on the host machine under:

```text
/home/<login>/data/
├── mariadb/
└── wordpress/
```

Replace `<login>` with the Linux username of the person running the project.

Removing or recreating containers does not normally delete these persistent data volumes.

**Warning:** the `make fclean` command removes persistent data. Back up important information before using it.
